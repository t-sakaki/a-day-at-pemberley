【イベントデータ構造】
interface EmergencyEvent {
  id: string;
  type: 'spill' | 'sick' | 'dog' | 'guest_arrival' | 'dinner_rush';
  title: string; // 表示用短いタイトル
  description: string; // 詳細説明
  location: string; // 発生場所（'kitchen', 'drawing_room', 'entrance' など）
  timeLimit: number; // 制限時間（秒、ゲーム内時間換算）
  remainingTime: number;
  severity: 'minor' | 'major' | 'critical';
  consequence: string; // 悪化時の次のイベントIDまたは効果
  resolved: boolean;
}

【イベント例（5種類）】
1. spill（コックがソースをこぼした）
   - 場所: kitchen
   - 制限: 30秒
   - 対応: 誰かをkitchenに送る、またはプレイヤーがkitchenでE連打
   - 悪化: 「朝食が遅れる」→ 全来客の怒り+15、館の評判-10

2. sick（庭師が風邪をひいた）
   - 場所: servant_quarters
   - 制限: なし（継続的）
   - 効果: 庭師が作業不能。庭園イベント発生時に対応者-1。
   - 対応: メイド長がservant_quartersに向かうと、20秒後に回復。

3. dog（犬が居間を汚した）
   - 場所: drawing_room
   - 制限: 25秒
   - 対応: メイドをdrawing_roomに送る
   - 悪化: 「来客が居間に入れない」→ 来客の怒り+25

4. guest_arrival（レディ・キャサリンが予告なしに到着）
   - 場所: entrance
   - 制限: 40秒
   - 対応: 東の客室（east_room）の準備度を80%以上にする、またはメイドをeast_roomに送る
   - 悪化: 「部屋が未準備」→ レディ・キャサリンの怒り+40、館の評判-20
   - 演出: 玄関前に紫色のキャラクター（既存の来客モデルを流用）が出現。玄関へ向かって歩く。

5. dinner_rush（急な晩餐会の依頼）
   - 場所: kitchen
   - 制限: ゲーム内時間で夕食時まで（例：17:00まで）
   - 対応: 台所の食事準備度を80%以上にする
   - 悪化: 準備度が不足→ 全来客の怒り+20、館の評判-15

【連鎖メカニズム】
- イベントAを「放置」（timeLimitが0になる）すると、自動的にconsequenceが発火。
- consequenceは「新しいイベントBを生成」または「直接ゲージに影響」。
- 例：spill（放置）→ 自動生成「delayed_breakfast」→ さらに放置すると「angry_guest」

【プレイヤーの対応方法】
1. 召使いをクリック/タップして選択 → パネルまたはコンテキストメニューで「Go to [場所]」を選択。
2. 召使いが現場に到着すると、自動的にイベント解決が進行（5秒で解決）。
3. プレイヤー自身が現場にいる状態でEキー（またはアクションボタン）を連打すると、解決が3秒で完了（手助け）。

現在の単一「館の評判」ゲージを、以下に分離して右上に表示：

1. 「館の評判」（Reputation）：星5つ表示（0-100%）。全体的な評価。
2. 「来客の機嫌」（Guest Mood）：現在の来客名と怒りゲージ（0-100%）。
3. 「召使いの士気」（Staff Morale）：0-100%。低いと召使いの移動速度と作業速度が半減。

【士気システム】
- イベントが連鎖して放置されると、士気が低下。
- 士気が30%以下になると、召使いが「疲労」状態になり、作業速度が半減。
- プレイヤーが直接手助けすると、士気が5%回復。
