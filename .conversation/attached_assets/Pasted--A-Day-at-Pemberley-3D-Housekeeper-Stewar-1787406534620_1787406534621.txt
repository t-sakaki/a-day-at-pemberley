【ゲーム概要】
タイトル："A Day at Pemberley — ペンバリーの一日"
ジャンル：3Dリアルタイム領地経営シミュレーション
視点：召使い長（Housekeeper/Steward）の一人称/三人称視点。ペンバリー風のオースティン的邸宅とその領地を、3D空間でリアルタイムに管理する。

【技術要件】
- 単一の index.html ファイルで完結。すべてのコード（HTML/CSS/JS）をこの1ファイルに含める。
- Three.js は CDN から読み込む（https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js）。
- 外部ライブラリは使用しない。OrbitControls も含めて独自実装するか、three.js examples からの CDN 読み込みを同ファイル内で行う。
- ブラウザ上で直接動作。Replit の "Run" ボタンで即座にプレビュー表示されることを前提。
- 画面サイズはウィンドウサイズにフルレスポンシブ対応。

【3Dワールド仕様】
マップ構成（ローポリゴン・プリミティブで構築）：
1. 邸宅本館（2階建ての簡易立方体。外壁はクリーム色、屋根はスレートグレー）
   - 内部フロアも同じシーン内に配置し、カメラで部屋間を移動する（ロード画面なしのシームレス設計）。
   - 配置する部屋：玄関ホール（中央階段）、食堂（大テーブル）、居間（暖炉）、客室×3（ベッド+窓）、執務室（プレイヤーの起点）、台所（調理台）、使用人部屋。
2. 庭園（邸宅前方）：整形式庭園をイメージ。幾何学的な低木（緑の箱型）、バラ壇（赤/ピンクの円盤）、並木道（円柱の木が左右に並ぶ）。
3. 庭師小屋（庭園奥）：小さな茶色い立方体。
4. 馬車置き場（邸宅横）：屋根付きの簡易構造。
5. 領地の小道：地面は緑色平面。小道は薄いベージュの帯。

キャラクターモデル（すべてローポリ・プリミティブ）：
- 召使い：円柱（体）+ 球（頭）+ 4本の細い円柱（手足）。色で区別。
  - 執事：黒 / メイド長：白エプロン（前面に白い板） / 庭師：緑 / コック：白 / 使用人：紺
- 来客：より小さな円柱群。服装色で地位を暗示（レディ・キャサリンは紫色）。
- プレイヤー：カメラ自体がプレイヤー視点。他の召使いから見た時に、プレイヤー位置に青い球体を表示。

ライティング：
- DirectionalLight（太陽/月）：時間帯で色が変化。朝はオレンジ、昼は白、夕方は赤紫、夜は青白い。
- AmbientLight：環境光。夜間は弱くなる。
- PointLight：各部屋の暖炉/シャンデリア。夜間のみ強く発光。
- シャドウマップを有効化（renderer.shadowMap.enabled = true）。

カメラ：
- デフォルトは「執務室俯瞰」から始まり、WASD で水平移動、マウスドラッグで視点回転、スクロールでズーム。
- 部屋の天井は通常時は非表示（トップダウン的に見下ろせるように）、屋外では通常視点。

【ゲームシステム詳細】
時間進行：
- ゲーム内1日 = 実時間24分（1時間 = 実時間1分）。
- 朝6時に開始。21時で1日終了し、日記画面へ。
- 時間は画面右上にアナログ時計風に表示（Three.js の CanvasTexture で描画しても、HTMLオーバーレイでも可）。

季節サイクル：
- 1日ごとに季節が進行（春→夏→秋→冬→春）。
- 庭園の木の色が変化（春：薄緑、夏：濃緑、秋：橙、冬：茶色＋雪のパーティクル）。
- 空の背景色も変化（Horizon色の補間）。

召使いAI（5名）：
- それぞれに「役割」と「スケジュールリスト（目的地と作業の配列）」を持つ。
- 状態機械：移動中 → 作業中（目的地で停止、作業アニメーション：上下に小さくバウンド） → 待機 → 次の移動。
- 移動は3D空間で、目的地のVector3に向かって毎フレームlerp移動。障害物は単純に迂回（経路探索は不要、部屋の入り口を通るように配置する）。
- 作業効率：各召使いが作業中に、その部屋の「清掃度/整備度」ゲージが上昇。
- 疲労度：召使いにも疲労ゲージがあり、使用人部屋で回復。

プレイヤー操作：
- WASD：水平移動。Shift：走る。
- Eキー：対話・調査・指示。召使いに近づいてEを押すと、ポップアップメニューで指示を出せる（「ここを掃除して」「食堂に行って」「鐘を鳴らす」）。
- 鐘システム：執務室の鐘をEで鳴らすと、全召使いが一時的に執務室前に集合。緊急時用。

作業ゲージ（各部屋）：
- 清掃度（0-100%）：下がり続ける。100%で「完璧」、50%以下で「不潔」。
- 食事準備度（台所のみ）：昼食/夕食の時間に合わせて上げる必要がある。
- 客室準備度：来客がある部屋のみ重要。

評判システム：
- 画面左側に「評判ゲージ」（0-100%）。
- 来客がいる間、リアルタイムで減少し続ける。不満イベントで大幅減少。
- 来客の不満は、画面右下にチャットログ風にテキストが流れる（HTMLオーバーレイ）。

突発イベント（リアルタイム発生）：
1. 「レディ・キャサリンが予告なしに到着！」→ 玄関前に紫色の来客が出現。客室の準備度が即座に要求される。準備ができていないと評判が30%低下。
2. 「雨で庭園の並木道がぬかるむ！」→ 庭園エリアの移動速度が半減。庭師の作業優先度が上がる。
3. 「コックが風邪をひいた」→ 台所作業が1人減る。プレイヤーが代わりに台所でE連打で手伝える。
4. 「犬が居間の絨毯を汚した」→ 居間の清掃度が即座に0%。
5. 「急な晩餐会の依頼」→ 夕方に、食事準備度を80%以上にする緊急クエスト。
イベント発生時は画面中央上部に赤いバナーで通知。

【BGM・音声仕様】
BGM（プロシージャル生成）：
- Web Audio API の OscillatorNode と GainNode を使用し、プロシージャルに生成。
- 曲調：18世紀風のクラシック（ピアノ風の和音進行）。簡易的なアルペジオで十分。
- 時間帯で変化：朝（穏やかな長音）、昼（やや明るいアルペジオ）、夕方（哀愁のある短調風）、夜（静かな単音）。
- 季節でも音色を微調整（春：明るい、冬：少し重い）。
- 常時ループ再生。音量スライダーは設定画面に配置。

効果音（SE）：
- 鐘の音（高いピング音）、足音（低いノイズ短音）、イベント発生音（短い和音）、作業完了音（きらきら音）。すべて Web Audio API で生成。

TTS / Web Speech API：
- 以下のタイミングで発話する：
  a) 突発イベント発生時（「レディ・キャサリンが到着されました」）
  b) 来客の不満ログが流れた時（「居間が不潔ですわ」）
  c) 評判ゲージが50%を下回った時（警告）
  d) 1日終了時の日記画面で、今日の出来事を要約して読み上げ
- SpeechSynthesisUtterance を使用。言語設定に応じて発話言語を切り替える（en-GB, ja-JP, fr-FR, de-DE, es-ES, zh-CN）。
- 初回ゲーム開始時、ユーザーがクリックした後に TTS を有効化（ブラウザの自動再生ポリシー対策）。
- 設定画面で「音声 ON/OFF」「音声速度（0.5〜2.0）」を調整可能にする。

【国際対応（i18n）仕様】
対応言語：英語（英国）、日本語、フランス語、ドイツ語、スペイン語、中国語（簡体字）。
実装：
- ゲーム開始時に言語選択モーダルを表示。6つの国旗アイコンと言語名を表示し、クリックで決定。
- すべてのUIテキスト、イベントテキスト、会話テキスト、ボタンラベルを i18n オブジェクトで管理。
- 言語切替後、即座に全UIが更新される。
- TTS の発話言語も同時に切り替わる。

【UI/UX仕様（HTMLオーバーレイ）】
画面上部：
- 左：季節アイコン + 天候アイコン + ゲーム内日付（"Day 1 - Spring"）
- 中央：評判ゲージ（星5つ表示、リアルタイムで減る）
- 右：アナログ時計（ゲーム内時間）

画面左下：
- ミニマップ（Canvas 2D で描画。邸宅の見取り図。プレイヤーと召使いの位置をドットで表示）。

画面右下：
- イベントログ（来客の不満、召使いの報告などが上から下へ流れるチャット風）。最新5件表示。
- クリックで履歴を展開。

画面下部中央：
- 現在の場所名（「執務室」「食堂」「庭園」など）。

画面右側（折りたたみ可能）：
- 召使い一覧パネル。各召使いの名前、現在の状態（移動中/作業中/疲労）、現在いる部屋。クリックでカメラがその召使いにフォーカス。

ゲーム開始時：
- タイトル画面を表示。背景はペンバリーの外観3Dビュー（カメラがゆっくり回転）。
- 「START GAME」ボタンを押すと言語選択→ゲーム開始。

【日記システム（1日終了時）】
- 21時になるとゲームが一時停止し、日記画面へ。
- 今日の出来事をテキストで自動生成（「3件のイベントが発生しました。評判は72%でした」）。
- プレイヤーはテキストエリアに「今日の感想」を3行まで入力可能。
- LocalStorage に保存され、翌日以降「過去の日記」ボタンで閲覧可能。

【コードアーキテクチャ（クラス構成）】
以下のクラス/モジュールを、単一ファイル内に明確に区切って実装（コメントでセクション分け）：

1. I18n：言語データと翻訳関数 t(key)。
2. AudioManager：BGM生成・SE生成・TTS発話・音量管理。
3. TimeSystem：ゲーム内時間・季節・天候の管理。
4. Estate：邸宅の部屋データ、ゲージ管理。
5. Staff：召使いのAI、行動状態、3Dメッシュ。
6. Player：プレイヤー移動、カメラ制御。
7. EventManager：突発イベントの抽選・発生・管理。
8. Reputation：評判計算、ログ生成。
9. World3D：Three.js シーン構築、ライティング、マップ生成、アニメーションループ。
10. Game：メインループ（requestAnimationFrame）、状態管理、初期化。

【実装上の重要注意】
- Three.js の読み込み後に初期化を行う。window.onload または script タグの onload で開始。
- シャドウは PCFSoftShadowMap を使用。性能が重い場合、シャドウ解像度は1024x1024以下に。
- 召使いの数は5体。木の数は庭園に10本程度に抑え、パフォーマンスを確保。
- TTS は、ブラウザが対応していない場合（一部モバイル）でも、テキストログのみでゲームが成立するようにフォールバック。
- BGM はユーザーが「START GAME」をクリックした後に初めて再生開始（自動再生ポリシー対策）。
- 単一ファイルで完結するため、画像アセットは使用せず、すべて Three.js の基本ジオメトリと CanvasTexture で生成する。例：木は CylinderGeometry + ConeGeometry、絨毯は PlaneGeometry with colored material。

【出力要件】
- 単一の index.html ファイルとして、完全に動作するゲームを作成。
- コードは十分にコメントを入れ、各クラスの責務が分かるようにする。
- Replit で「Run」を押した瞬間に、タイトル画面が表示され、クリックでゲームが開始される状態にする。
- コンソールにエラーが出ないように実装。
